# Implementation Plan: Front-Page Toggle Between Threads and Gallery

**Status: implemented.** Automated handler tests pass; visual browser/mobile
verification remains a manual check.

## Overview

The front page (`/`) and the image wall (`/gallery`) are two separate pages,
but the only way to move between them today is the collapsed mobile nav or a
navbar link. This plan adds one prominent, mobile-friendly switch — **Threads |
Gallery** — at the top of both pages, so changing views is a single tap.

The switch is Bulma's **tabs** component rendered as server-side navigation: no
JavaScript, no new endpoint, no schema change. `/` remains threads and
`/gallery` remains the image wall, so existing links, pagination, tests, and
bookmarks keep working.

## Goals

- A clear two-option switch is visible near the top of the front page and the
  gallery without opening the navbar.
- The active view is obvious visually and to screen readers.
- One tap switches views; the URL remains the durable state (`/` vs `/gallery`).
- Works with the existing dark/light theme, mobile width, and keyboard focus.
- Minimal surface area: one shared template partial, Bulma tab classes, two
  handler data fields, and focused tests.
- Use Bulma's existing tabs component (`tabs is-toggle is-toggle-rounded
  is-fullwidth`) instead of bespoke switch CSS.

## Non-goals

- Merging the gallery into `/` (e.g. `/?view=gallery`).
- Remembering the last chosen view in a cookie or `localStorage`.
- Infinite scroll, combined filtering, or a gallery search.
- Removing the existing navbar Gallery link or changing the gallery query.
- Changing pagination semantics; switching views resets to page 1.

## Current-state facts that shape the design

- `IndexPage` (`internal/handlers/front.go`) renders `index.html` and already
  passes a data map. `GalleryPage` (`internal/handlers/gallery.go`) renders
  `gallery.html` with its own data map. Both go through `app.render`, which
  injects `CurrentUser`, theme, flash messages, etc.
- Page templates are parsed together with `layout.html` in `NewApp`
  (`internal/handlers/app.go`). A shared `{{define}}` partial must be added to
  that parse list, exactly like `thread_rows.html` and `reaction_bar.html`.
- Both pages use the same shell: `section.card.forum-section.my-5` with a
  `card-header`. On the index, an “On the air” strip currently precedes the
  card; the gallery has no online strip.
- Bulma v1 is vendored and already provides the tabs component, including
  `.tabs`, `.tabs.is-toggle`, `.tabs.is-toggle-rounded`, and
  `.tabs.is-fullwidth`. No new component CSS is expected.
- If a spacing tweak is needed, the genuine stylesheet source is
  `web/css/site.css`. `web/static/disjoint.css` is generated by `make css`
  (Bulma theme extraction + `web/css/site.css`), so never hand-edit the
  generated file.
- Existing tests assert the navbar Gallery link
  (`internal/handlers/gallery_test.go`). Keeping that link avoids churn.
- The app already uses `aria-current`/semantic links in places. These are
  Bulma **tabs visually**, but not ARIA tabs semantically: each link performs a
  full-page navigation, so `aria-current="page"` is correct and a
  `role="tablist"` would promise in-place panel switching and keyboard
  arrow-key behaviour that this design deliberately does not implement.

## Architecture Decisions

### A. Two real URLs, one shared switch

Keep `/` and `/gallery` as the two views. The switch is a pair of `<a>` links,
not a form or JS toggle. Benefits:

- Works without JavaScript and with middle-click / open-in-new-tab.
- No state to hydrate, no flash of the wrong view.
- Existing routes, caching headers, tests, and pagination stay valid.
- The browser’s back button naturally returns to the previous view.

Rejected: `/?view=gallery` (adds branching to the index handler and makes the
already-working `/gallery` route redundant) and a client-side hide/show of both
views (downloads both payloads, breaks without JS, and is harder to paginate).

### B. Shared partial: `web/templates/view_switch.html`

Add `{{define "view_switch"}}` using Bulma's tabs component:

```html
<nav class="tabs is-toggle is-toggle-rounded is-fullwidth"
     aria-label="Front page view">
  <ul>
    <li{{if eq .View "threads"}} class="is-active"{{end}}>
      <a href="/"{{if eq .View "threads"}} aria-current="page"{{end}}>Threads</a>
    </li>
    <li{{if eq .View "gallery"}} class="is-active"{{end}}>
      <a href="/gallery"{{if eq .View "gallery"}} aria-current="page"{{end}}>Gallery</a>
    </li>
  </ul>
</nav>
```

The partial is parsed into every template set in `NewApp`, next to
`thread_rows.html`, and included as `{{template "view_switch" .}}` near the top
of `index.html` and `gallery.html`. The `.View` value is supplied by the two
handlers (`"threads"` / `"gallery"`), rather than inferred from the request path
inside the template. Bulma's active state lives on the `<li>`
(`li.is-active`); `aria-current="page"` stays on the active link for assistive
technology.

### C. Placement: directly above the content card

- **Index:** after the “On the air” strip, before the threads card.
- **Gallery:** at the top of the page, before the gallery card.

This puts the switch in the first screenful on mobile (the user’s screenshot is
the gallery header) without touching the navbar or the card header. The
existing card titles (“Threads”, “Results for …”, “Gallery”) and the `+`
header action remain unchanged, so search-result headings keep working.

### D. Styling: Bulma tabs, no bespoke switch CSS

Use Bulma's tabs classes directly:

- `tabs` — base component (link colors, hover, active state, focus).
- `is-toggle` — connected segmented-control appearance.
- `is-toggle-rounded` — rounded outer ends, matching the app's controls.
- `is-fullwidth` — each tab grows equally, so the switch fills the container
  and is a comfortable tap target on mobile.

No `.view-switch` CSS block is added. If spacing needs adjusting between the
switch and the surrounding card, prefer a Bulma spacing utility (e.g. `mb-4`)
before adding custom CSS. If a theme contrast issue is found during manual
verification, add a minimal override to `web/css/site.css` and regenerate with
`make css`.

### E. Keep the navbar link and page titles

The navbar “Gallery” link stays for deep access from any page and to keep the
existing gallery test stable. The switch is an additional front-page
affordance, not a replacement for global navigation.

## Acceptance Criteria

- A user on `/` can switch to the gallery with one tap/click without opening the
  nav; a user on `/gallery` can switch back the same way.
- The current view is visually distinct and announced via `aria-current="page"`.
- No JavaScript is required; both views remain independent, linkable pages.
- No route, database, query, or pagination behaviour changes.
- The switch is rendered with Bulma's `tabs`, `is-toggle`, `is-toggle-rounded`,
  and `is-fullwidth` classes; `li.is-active` marks the current view.
- `go test ./...` passes.

## Risks / Follow-ups

- **Template parse regression:** forgetting to add `view_switch.html` to the
  parse list makes both pages fail at render time. Covered by the handler tests.
- **Bulma styling mismatch:** `is-toggle` may look heavier than the surrounding
  card. Verify in both themes; fall back to `is-boxed` if needed rather than
  inventing a custom switch. If an override is genuinely required, edit
  `web/css/site.css`, not the generated `web/static/disjoint.css`.
- **Future enhancement (out of scope):** let the logo remember the last view,
  or make the gallery an HTMX swap on `/`. Both can build on the same two URLs
  and partial without changing this design.
